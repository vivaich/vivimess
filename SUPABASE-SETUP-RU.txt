ViviMess 5.7 — подключение постоянного хранения Supabase

Что изменено
- Сервер загружает общую базу ViviMess из public.vm_data (строка id=main) при старте.
- Каждое сохранение отправляет актуальный снимок базы в Supabase.
- Записи выполняются последовательно, чтобы более старое сохранение не затёрло новое.
- Локальный data.json остаётся режимом разработки, если обе переменные Supabase не заданы.
- Секретный ключ используется только на сервере. Не добавляйте его в public/app.js, HTML или CSS.

Настройка Render
1. Откройте Render → ваш сервис ViviMess → Environment.
2. Добавьте SUPABASE_URL = https://owasngkcohkecmzgmlxk.supabase.co
3. Добавьте SUPABASE_SECRET_KEY = Secret key из Supabase → Project Settings → API Keys.
   Не используйте sb_publishable_... — это не Secret Key.
4. Сохраните изменения и запустите новый deploy этой версии.
5. В логах запуска должно появиться: (Supabase persistence enabled).

Таблица
Ожидается public.vm_data с колонками:
- id text PRIMARY KEY
- data jsonb NOT NULL
- updated_at timestamptz NOT NULL

Именно такую таблицу мы создали SQL-запросом в Supabase. RLS можно оставить включённым без публичных политик: сервер обращается к таблице с Secret Key.

Важно
- Впервые подключаем новую пустую облачную базу: старые локальные аккаунты не импортируются.
- После успешного запуска первая запись будет создана автоматически.
- Supabase Free имеет ограничения по объёму и активности проекта. Это не обещание бесконечного бесплатного хранения.
- Сообщения с вложениями/медиа сейчас тоже хранятся в JSONB как часть общей базы; при большом объёме потребуется отдельное файловое хранилище.
